# Weaver Ash / AshR2RML / Reactor Wrapper

This directory is an additive BEAM control plane around the existing OpenTelemetry Weaver Rust binary. It does **not** replace Weaver's semantic-convention parser, policy engine, registry resolver, generators, or CLI.

## Standing

The wrapper implements this correspondence:

```text
public RDF/SHACL ontology
        |
        v
       ggen                     SELECT + CONSTRUCT only
        |
        v
generated operation contract
        |
        +--> Ash resources --> AshR2RML normalized mapping / R2RML
        |
        v
      Reactor                   orchestration, zero automatic DO retry
        |
        v
  WeaverAsh.Runtime             exclusive process authority
        |
        v
 exact Weaver executable + local registry subject
        |
        v
      receipt                   executable/subject/output SHA-256 + argv + exit
```

The Rust Weaver binary remains the authority on whether an OpenTelemetry semantic-convention registry is valid. The wrapper adds semantic interoperability, bounded orchestration, and receipted execution.

## Public ontology alignment

`ontology/weaver-ash.ttl` aligns wrapper concepts to public vocabularies rather than declaring OpenTelemetry semantic conventions to be an RDF ontology:

- **DCAT** — a Weaver registry is a specialization of `dcat:Dataset`; a packaged registry is a specialization of `dcat:Distribution`.
- **PROV-O** — execution is a specialization of `prov:Activity`; a receipt is a specialization of `prov:Entity`; completion is projected with `prov:generatedAtTime`.
- **DCTERMS** — source/revision metadata.
- **SKOS** — operation concepts.
- **SHACL** — admissible operation/authority constraints.
- **R2RML** — generated by `AshR2RML.Resource` from the Ash resources in `lib/weaver_ash/resources.ex`.

No `owl:equivalentClass` assertion is made between OpenTelemetry concepts and these vocabulary classes.

## Authority fence

v0.1.0 admits exactly three operations against a **local, hashable registry subject**:

| Operation | Weaver argv shape | Additional authority |
| --- | --- | --- |
| `check` | `registry check -r <local>` | none |
| `stats` | `registry stats -r <local>` | none |
| `package_json` | `registry package -r <local> -t json [--id ID]` | optional package id |

The following are typed `REFUSED` before actuation: raw argv/shell commands, remote registry URLs, operation-contract widening beyond the runtime fence, `generate`, `emit`, `live-check`, `mcp`, `infer`, `serve`, and every unknown operation. A registry tree containing symlinks is also refused until symlink identity semantics are explicitly admitted.

The ontology and generated source do not possess ambient process authority. `WeaverAsh.Runtime` independently checks the generated contract against a finite subcommand/target fence and uses `System.cmd/3` with an argv list; there is no shell interpolation.

## Zero unreceipted actuation

Before process start the runtime resolves and hashes the Weaver executable and deterministically hashes the local registry tree. If either identity cannot be established, execution is refused. Once process execution is attempted, success, non-zero exit, or runtime exception produces a `WeaverAsh.Receipt` containing:

- exact executable path and SHA-256,
- canonical local registry path and deterministic subject SHA-256,
- exact argv,
- start/completion timestamps and duration,
- exit status when observed,
- SHA-256 and byte length of merged stdout/stderr,
- `ALIVE` for observed exit 0 or `PARTIAL_ALIVE` for a receipted non-success.

Reactor never automatically retries the Execute step.

## Manufacture and verify

From this directory, manufacture the committed projection with the exact ggen producer used by CI:

```bash
cargo +nightly-2026-06-22 run \
  --manifest-path /path/to/ggen/Cargo.toml \
  -p ggen-cli-lib --bin ggen -- sync run

git diff --exit-code -- lib/weaver_ash/generated/operation_contract.ex
```

The producer is pinned in CI to ggen commit `ddfa602bfbab57b7ed5150f61b0acac7a41e3020`. AshR2RML is pinned in `mix.exs` to `067954ad406fd637fd47646bdb10c4580809c79d`.

Local database-free checks:

```bash
mix deps.get
mix compile --warnings-as-errors
mix test
```

The integration crown additionally builds the exact Weaver repository head, extracts the repository's semconv test archive to a local tree, sets `RUN_WEAVER_INTEGRATION=1`, and executes `WeaverAsh.run("check", ...)` through Reactor. CI preserves the resulting JSON receipt as an artifact.

## Extension falsifier

An extension is not admitted merely because it can be represented in RDF or generated by ggen. To widen DO, it must add all of the following in one reviewable closure:

1. public-ontology/SHACL semantics,
2. deterministic ggen projection,
3. independent runtime fence support,
4. operation-specific adversarial refusal tests,
5. exact-subject integration execution,
6. a receipt that binds every consequential identity needed for replay.

Until that closure exists, the new edge is `REFUSED`, not implicitly available.
